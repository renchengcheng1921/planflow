# PlanFlow 开发步骤与验收计划

更新日期：2026-10-24。适用环境：Windows 开发机、已有 PostgreSQL/Redis、当前不采用 CI/CD。

本文基于用户提供的开发步骤和完整的 [AGENTS.md](../../AGENTS.md)，目标是提前解决阶段依赖和高成本决策，减少后期补权限、补审计、改数据模型及重写通知链路。

各阶段开发统一遵循 [统一开发规范](../standards/development.md)，较完整功能使用 [功能规格模板](../templates/feature-spec.md)，实际检查使用 [验收记录模板](../templates/verification.md)。本文件维护阶段与 Gate，命名/API/UI 等工程细则以统一规范为入口。

**状态：计划已整理，尚未开始业务实现。** 审查开始时仓库只有 AGENTS.md、初始 go.mod 和 IDE 文件；`docs/product/planflow.md`、应用代码、Makefile、测试及环境示例均未存在。下文所有命令、路径和 Gate 中尚不存在的部分均为待交付项，不能理解为已执行成功。

## 1. 本次审查的关键改进

| 原步骤的问题 | 调整 | 减少的返工 |
|---|---|---|
| S1 已要求 Activity，但 S2 才建 activities | S1 同步建立审计模型、事务接口和原子性测试 | 避免追补历史写操作和事务 |
| app 编排事务容易直接拿 GORM 句柄 | app 定义 Unit of Work 接口，repo 管理 GORM 和事务仓储 | 防止分层被破坏 |
| 全部手写 SQL 先于 AutoMigrate，新库可能没有目标表 | 明确前置 SQL / AutoMigrate / 后置 SQL；S0 验证新库和升级路径 | 避免首次部署与升级行为不同 |
| 假定 AutoMigrate 不会改列类型 | 按锁定的 GORM/驱动版本检查实际 schema diff，显式迁移高风险变更 | 避免迁移时意外改变已有列 |
| 收件箱、个人任务可见范围、今日计划归属未定义 | S-1/S1 明确工作区、用户和项目的权限边界；S2 定义收件箱语义 | 避免出现第二套 TODO 或泄漏个人任务 |
| 今日默认 7 项，但没有并发和确认超限协议 | S3 定义容量锁定、明确确认参数、重复请求幂等 | 防止多端同时写入绕过容量 |
| 只测依赖环检测函数 | S2 增加并发添加相反依赖的真实 PG 测试 | 避免分别合法的两次写入共同形成环 |
| S4 才考虑通知，S2/S3 只落库或临时直发 | S2 确定业务事务与通知事件的可靠交接；S4 消费同一链路 | 避免漏发、回滚后误发和批量补埋点 |
| 日报按工作区和日期去重，忽略收件人 | 按事件、接收人、渠道、周期等业务维度定义幂等键 | 避免一个用户收到后其他人收不到 |
| 把 SSE 当通知事实源 | PG 保存通知，SSE 只提示刷新；支持重连和按权限补拉 | 避免断线丢消息及多实例广播失效 |
| 软删除/重复任务/模板全压在一周收尾 | 软删除从 S2 开始，S6 拆为功能补齐和发布验收两个子阶段 | 避免临近发布改遍查询与唯一索引 |
| 保存视图提前放进 MVP，项目模板与任务模板混用 | 持久化多视图归 P1；MVP 模板与项目模板明确区分 | 避免范围漂移 |
| S0 部署 RustFS、S1 提前建 screen_tokens、安排假交互 | RustFS 到 S7，screen_tokens 到 S5；不做未实现的按钮/文案占位 | 减少维护无用基础设施和未来接口 |
| 大屏写请求一律期待 405 | 大屏路由写方法为 405；大屏 token 访问普通业务接口为 401/403 | 防止把 HTTP 方法限制误当权限检查 |
| 文件预签名 URL 与绝不暴露 bucket/key 存在冲突 | S7 前明确代理或直连取舍；默认建议代理，严格隐藏存储寻址 | 防止文件模块实现后整体改造 |
| 凭据测试要求所有响应无明文，与 reveal 目标冲突 | 仅授权、二次认证后的 reveal/copy 可返回一次性明文；其余响应无明文 | 防止写出无法满足的测试 |
| S7→S8 被描述为技术硬依赖，S9 子项宣称都可并行 | 保留先文件后凭据的推荐顺序；按实际依赖逐项排期 | 避免错误关键路径和重复造事件机制 |
| 固定宣称八周交付，缺少容量和环境假设 | 以阶段产物和 Gate 排期，S2 后按实际速度再估算 | 避免压缩测试和联调时间 |

## 2. 执行原则与范围

1. 每次实现一个小闭环：规则与契约 → 模型/迁移评估 → domain 测试 → app 编排 → repo → HTTP → UI → 验证。涉及模型时遵守 AGENTS.md 的模型优先修改顺序；不是业务表一次建完再统一联调。
2. 每阶段的输出都可实际使用。未完成能力不展示假交互；不以空迁移、空包、返回成功的空命令充当完成。
3. 关键决策先记录 ADR，再开发；尚未确认的产品语义写入待决清单并阻止依赖它的编码，允许推进独立事项。
4. 当前不配置 CI/CD、自动部署、远程流水线和平台门禁。本地 lint、测试、构建、迁移演练和人工检查仍是阶段退出条件。
5. 不提前实现 P1 文件/凭据、甘特、持久化多视图或 P2 能力；只维护路线图和必要的设计边界。
6. [ADR 0001](../decisions/0001-development-baseline.md) 记录环境、本地验收、事务边界与迁移流程。本文与 AGENTS.md 的相关调整同步维护，避免执行时出现两套约定。

### MVP 与后续范围

| 层级 | 交付范围 |
|---|---|
| MVP | 工作区、成员、项目、里程碑、统一 Task/子任务、看板/列表、收件箱、今日计划、日历时间块、复盘、评论/@、活动日志、标签、搜索、任务模板、重复任务、回收站、站内通知、每日摘要、大屏基础卡片、基础报表 |
| P1 | 文件/RustFS、敏感凭据、甘特/依赖可视化、保存多视图、工时、项目模板、自动化、API/Webhook、导入导出、工作区权限增强 |
| P2 | AI、OKR、资源负载、习惯打卡、白板、客户分享页等；本计划不安排实现 |

任务模板和重复任务是 MVP，项目模板和保存多视图是 P1。依赖无环规则属于 S2；完整依赖图/甘特交互属于 P1。报表 MVP 只交付能由已有任务和 Activity 数据支撑的基础指标，周报及更复杂统计不自动扩大范围。

## 3. 已有 PG/Redis 如何接入

### 3.1 开发与测试分开

- 日常运行直接连接已有服务，S0 不重复安装 PG/Redis。可选 Compose 仅服务于需要本地环境的人。
- PG 使用独立 PlanFlow 开发数据库及账号。自动测试使用独立测试数据库或独立临时实例；迁移账号和运行账号分别确定权限，不要求运行账号拥有建库或超级用户权限。
- Redis 最好给开发、测试分别使用独立实例。单机 Redis 的独立 DB 编号不能代替 ACL 隔离，集群通常只支持 DB 0；S0 验证 asynq 与实际部署模式的兼容性，不能假定改个 key 前缀就安全。禁止对共用实例执行 `FLUSHALL`/`FLUSHDB`。
- 集成测试优先 Testcontainers，在本机运行且锁定镜像版本。当前命令检索未找到 `docker`；S0 需确认可用 Docker 环境或准备独立测试服务。无 CI/CD 不代表不运行集成测试。
- 外部测试服务必须通过显式测试配置、目标白名单和隔离校验；没有隔离条件时阻塞相关 Gate，不自动改用开发数据，也不静默跳过测试。

### 3.2 到 S0 接入时需要的信息

| 服务 | 需要提供或确认 |
|---|---|
| PostgreSQL | host、port、database、username、password、服务器版本、TLS/sslmode、网络可达性、迁移权限、是否含已有业务数据 |
| Redis | host、port、ACL username（如有）、password、TLS、版本、单机/Sentinel/Cluster 模式、可用隔离方式、持久化与淘汰策略 |
| 测试资源 | 独立 PG 数据库/实例与账号；独立 Redis 实例；或本机 Docker 可用性 |
| 运行入口 | 浏览器访问的 Web/API 域名与端口、是否通过反向代理同源访问；影响 Cookie、CSRF、SSE |

账号密码只在实际接入时进入本机环境变量或忽略提交的 `.env`，不写入本文、ADR、截图、命令记录或 Git。`.env` 需要由启动脚本显式加载到进程环境，不能假定 Viper 会自动读取 dotenv。示例只留空值或说明，不写可用密码；输出诊断时只显示必要的非敏感连接信息。

环境变量统一 `PLANFLOW_` 前缀，由 S0 的强类型 Config 确定精确字段，例如 `PLANFLOW_DB_HOST`、`PLANFLOW_DB_PASSWORD`、`PLANFLOW_REDIS_ADDR`、`PLANFLOW_REDIS_PASSWORD`。不再维护另一套 `DB_*`/`REDIS_*` 别名。MVP 启动不读取或要求 Storage/KEK 配置。

- [ ] 归档产品方案原文；原文未提供前，以 AGENTS.md §15 为阶段范围依据，把整理稿标为“待确认”，不冒充产品原文。
- [ ] 建立“需求 → 阶段 → 页面/API → 验收用例”的范围矩阵，MVP 任务模板与 P1 项目模板分别列项。
- [ ] 统一 ID 方案、UTC 时间格式、分页约定、错误 code、版本冲突协议、日期与时间点字段的区别；数据库约束覆盖跨工作区关联。
- [ ] 定义个人收件箱：任务创建者、负责人和项目可见性的关系；快速收集不能自动变成全工作区可见。只使用 Task，通过明确的收件箱归类字段/规则表达未整理状态，不用 `project_id IS NULL` 代替所有业务语义。

- [ ] 明确可配置状态流的配置范围、终态识别方式、状态删除/重命名和现有任务迁移规则；统计依赖状态语义而不是硬编码状态名称。
- [ ] 明确父子任务与依赖关系的区别；禁止自为父任务、父子环、跨工作区依赖；项目外依赖是否允许要先定。
- [ ] 明确完成、重开、到期、取消、归档、软删除对完成率/逾期率/历史趋势的影响；记录支撑指标所需的最小时间信息。
- [ ] 明确超限确认是允许显式越限还是要求先调整今日项目，并固定请求协议。推荐首次 409，确认后再次提交显式覆盖标记；服务端在同一事务重新检查权限/容量并记录 Activity。
- [ ] 形成 action × 角色 × 资源范围矩阵，覆盖工作区/项目/个人任务；明确项目角色覆盖规则、离组失权、最后一名 OWNER 保护。

## 6. S0：工程和本地验证基础

**主要路径：** 根 `go.mod`、`Makefile`、`.gitignore`、`.env.example`、`config.example.yaml`、`scripts/`、`services/api/cmd/{api,worker,migrate}`、`services/api/internal/platform/`、`services/api/internal/repo/`、`services/migrations/`、`apps/web/`。

1. 核对根 go.mod 当前的 `module planflow` / `go 1.27` 与 AGENTS.md 的模块约定；确认可用稳定工具链后统一模块路径和版本。明确单 Go module、命令工作目录、pnpm workspace、锁文件和工具版本；不在多个目录重复初始化同名 module。
2. 建 Config/Viper 单次加载、环境绑定、Validate、Zap、Clock、ID、PG/Redis 连接、超时和连接池；DB 初始化由 platform 装配 repo 提供的 GORM 工厂，业务不依赖 GORM。
3. 建 API、worker、migrate 入口和优雅退出；worker 此时只做基础进程生命周期，不注册空的业务任务或未实现渠道。
4. 区分 `/healthz`（进程存活）和 `/readyz`（依赖可用），DB/Redis 探活有超时，不返回 DSN 或底层密码；依赖断开时 ready 失败、恢复后可恢复服务。
5. 建统一迁移器：进程间锁、SQL 版本/校验和、事务/非事务分类、前置与后置目录。顺序是前置 SQL → AutoMigrate → 后置 SQL；所有应用测试复用同一入口。S0 没有业务模型时只验证迁移器机制，不创建未来业务空表；S1 首批模型落地后补全业务 schema 演练。
6. 验证前置 SQL 不依赖尚未存在的新表；后置 SQL 才增加新表约束/回填。`CREATE INDEX CONCURRENTLY` 不包在普通事务里，处理失败残留；已成功版本不得修改。前置/AutoMigrate/后置整个流程不保证原子回滚，失败后需识别已成功步骤并可恢复。AutoMigrate 可能随字段差异修改类型或可空性，锁版本并审查实际 schema diff，不把它当成“只做新增”。api/worker 不自动迁移；测试和正式入口不能各写一套 AutoMigrate 模型清单。
7. 建 Next.js 布局、i18n、错误映射、空/错/加载态模式、TanStack Query 的 key 规范和用户/工作区切换清缓存策略。用户相关请求显式避免跨用户缓存，API DTO 不复制成 Today/Inbox 第二套 Task 模型。
8. 实现本地命令入口及 PowerShell 兼容方式。`make lint`/`make test` 等必须真实运行工具；尚无 E2E 时明确说明，首个可用页面闭环后落实 Playwright，不用空脚本返回成功。
9. 可选 Compose 只按需提供 PG/Redis 和邮件测试服务，锁定镜像版本、无硬编码密钥；不创建 RustFS、storage/secrets 包或占位配置。

**Gate：** 开发 PG/Redis 连通并完成隔离确认；API/Web 可运行；lint、现有测试、构建通过；健康/就绪接口符合约定；迁移器空库/重复/失败重跑测试通过。记录本机 Docker 或独立测试资源是否就绪，未就绪不得进入依赖真实数据库的验收。

## 7. S1：认证、工作区、权限与审计

**模型：** users、workspaces、workspace_members、必要的 session/invitation 数据、activities。`screen_tokens` 到 S5 再建。

1. 先落认证 ADR：比较服务端 Session 与 JWT，决定 Cookie、过期/撤销、登出、多端会话、CSRF/CORS、Next.js 服务端转发认证及同源部署方式。浏览器原生 EventSource 不便设置任意 Authorization 头，SSE 鉴权需在此验证，不能把 token 放入 URL。
2. 实现密码安全散列、注册/登录/退出、登录限流、会话过期/撤销；默认拒绝未知 action 和资源类型。公开 auth/health 路由明确白名单，业务路由一律鉴权授权。
3. 工作区创建/切换、成员邀请/接受/撤销/过期、角色变更和移除；邀请 token 仅存摘要、单次使用。邮件尚未接入时可交付管理员获取邀请链接并手动分享的实际闭环，链接不进日志和审计摘要。
4. app 定义事务接口，repo 返回绑定同一 GORM 事务的业务仓储与 Activity 仓储。app 不接收 `*gorm.DB`；业务和审计任一失败全部回滚。首批写操作就启用 Activity，明确系统 actor 与认证事件允许记录的安全字段。
5. 工作区作用域纳入每个 repo 查询，授权检查资源实际所属范围；不仅校验 URL 的 workspace_id。明确个人任务与项目继承策略的权限用例，为 S2 接口复用。
6. 安装固定中间件链与集中 errors.go，测试 binding/校验错误走统一响应；前端交付登录、退出、工作区切换和成员管理。

**Gate：** 登录/退出/邀请 E2E；过期和撤销生效；双工作区横向越权 403/404；VIEWER 写入被拒；成员变更与 Activity 原子性；日志无密码/token/Cookie；S1 schema 的全新初始化、再次迁移和升级测试通过。

## 8. S2：项目、任务、里程碑与协作基础

**模型：** projects、必要的 project_members/status 配置、milestones、tasks、task_dependencies、task_comments、tags、task_tags；Activity 复用 S1。事件持久化结构按本阶段 ADR 引入，服务于已实现业务。

1. 按已确认的范围建立统一 Task，包含工作区、可空项目、负责人、创建者、父任务、到期/完成时间、版本和软删除字段；明确无项目任务的可见性和收件箱归类。
2. 完成项目/里程碑/任务 CRUD、子任务、指派、状态变更和阻塞字段。父子关系、依赖关系都验证作用域和环；在事务内按确定顺序锁定适当的图范围，串行化可能共同形成环的写入，不能只读图后各自插入。
3. 引入版本条件更新或等效乐观锁，冲突稳定返回 409 CONFLICT；统一更新版本条件和 Activity 写入。测试并发覆盖、陈旧版本请求、批量排序的稳定性。
4. 从首版查询启用软删除。定义项目/任务删除后子任务、依赖、评论、今日引用的可见性和恢复策略；软删除后的业务唯一键与恢复冲突须用真实 PG 验证，不能假定 `deleted_at` 加进联合唯一键就足够。
5. 完成标签、评论、回复及 @ 提及的用户引用和权限检查；不把评论文本简单扫描出来的任意 ID 当作有效收件人。
6. 在此阶段落通知可靠交接 ADR。推荐业务写入、Activity、待处理事件同事务落 PG，由 worker 经 `notify.Emit` 进入规则引擎；确认事务型 outbox 与重试/领取/恢复语义。不得在事务提交前投递或提交后只入 Redis 而无补偿。S4 尚未投递的事件标记为待处理，联调事件的回放/过期范围需明确，不能上线时突然发送所有旧提醒。
7. 实现分页、稳定排序、白名单过滤；项目列表、任务看板/列表、详情抽屉、评论/标签 UI；定义健康度公式，只含进度/逾期/阻塞等 MVP 数据，不引入资源负载。

**Gate：** CRUD/指派/评论 E2E；自环/多节点环/合法 DAG；并发相反依赖与父子环防护；跨工作区关联拒绝；冲突返回；软删除默认过滤；Activity/事件与业务同成功同回滚；不直接调用渠道客户端。

## 9. S3：收件箱、今日、时间块与复盘

**模型：** today_plans、today_plan_items，必要的复盘/顺延确认记录；只引用 Task，不复制任务内容。

1. TodayPlan 唯一键含 workspace_id、user_id、plan_date；计划日期按工作区时区计算，计划项禁止重复引用同一任务。日期是本地日历日期，不用 UTC 午夜简单截断代替。
2. 加入今日时锁定该计划并在事务内检查容量和重复项；并发创建计划使用唯一约束兜底再安全重试。首次超过默认 7 项返回 409 TODAY_FULL，确认后的重试遵循 S-1 确定的协议，再校验权限和当前计划，并写审计；不能靠前端弹窗绕过后端限制。
3. 排序、时间块、移出今日、完成任务复用 Task 用例；移出计划不能软删除 Task。任务完成后其他视图及时同步，任务删除后历史计划以已定义方式呈现。
4. 工作区时区 + 注入 Clock 计算边界；测试跨日、DST、重复/不存在的本地时间。时间块有效性、跨日/重叠规则由服务端校验。
5. 结算未完成项生成待顺延候选；不改成 Task 的新状态、不自动写入下一天。用户确认时检查新一天容量，幂等地添加引用并记录来源；历史计划保留可复盘。
6. 交付“今日必做 / 时间块 / 收件箱待整理”、全局快捷收集与悬浮按钮、日历、复盘。日历拖拽复用同一 API，失败回滚并提示；明日候选是真实数据和显式确认，不做智能建议占位。

**Gate：** 收集→加入今日→完成→复盘 E2E；6 项时两端同时添加、7 项同时确认超限、重复点击/重复顺延、移出不删任务；时区与跨日测试；用户之间的今日计划隔离。

## 10. S4：通知、worker 与实时刷新

**模型：** notifications、规则/订阅/聚合/投递状态所需表；复用 S2 的可靠事件，不新建第二条业务事件链。

1. 事件清单集中在 notify/events.go，先覆盖指派/@/回复/到期/逾期/状态变更/里程碑和每日摘要。URGENT 的来源和升级条件明确，不让普通业务随意升级。
2. 处理规则：匹配 → 级别 → 聚合 → 免打扰 → 渠道投递 → 通知记录；定义各阶段持久化状态和重试。通知记录、投递尝试、用户已读状态职责分清。免打扰期间非紧急事件延后或进入摘要，具体语义先定，不能静默丢失。
3. 幂等键按语义包含 event/recipient/channel；摘要按 workspace/user/period/channel；聚合按 recipient/resource/window 等维度。数据库唯一约束兜底，重试不会增加可见通知；渠道外部调用可能至少一次，不能宣称邮件绝对只发一次。
4. worker 消费 asynq，处理待处理事件、重试、进程中断恢复、死信状态与可人工重放；Redis 故障时 PG 中事件保留，恢复后补投。外部投递不放在业务数据库长事务内。
5. 多实例调度通过唯一约束/租约避免重复执行；按工作区时区和本地日期调度到期/摘要，补跑不能跨周期乱发。使用测试 Clock 推进时间，不 sleep 等待。
6. 站内默认开启；邮件默认关闭，只有配置渠道且用户订阅后才发送。IM 到需要时再实现，不做空渠道。SSE 鉴权、心跳、重连、失权后断开和多实例传播要测试；PG 查询可补拉通知，Redis pub/sub 或 SSE 不作历史事实源。
7. 前端通知列表、已读/全部已读、订阅/免打扰设置。已读等写操作遵守审计规则；如支持“一键完成任务”，必须调用标准 task.complete 权限/事务用例，不能绕过业务逻辑。

**Gate：** 聚合/免打扰/时区单测；重复事件与重复摘要幂等；回滚无误发；PG 提交后 Redis 暂停仍能恢复；worker 中断重试；死信可见并可重放；SSE 断线后按权限补拉，移除成员后失权；至少一次外部投递的限制有记录。

## 11. S5：大屏与基础报表

**模型：** 此阶段才创建 screen_tokens，包含摘要、工作区、范围、过期、撤销和强制脱敏策略；token 不以明文持久化。

1. token 创建/撤销走普通用户管理接口并留痕；展示数据路由只注册读取方法，token 只能用于限定大屏 action。原始 token 不进入 URL/query、日志或前端持久存储；选择短期兑换 Cookie 或受控请求头的方案并记录 ADR。
2. 大屏独立 DTO，字段白名单；复用授权后的聚合查询，排除个人收件箱私有信息及全部文件/凭据元数据。管理员设置的脱敏策略必须是服务端下限，页面开关不能解除 token 强制脱敏。
3. 今日焦点、项目健康、里程碑倒计时、逾期阻塞、动态流；分页/数量上限、刷新频率限制和 SSE 失效处理。撤销在下一次请求立即拒绝，已有 SSE 连接也需主动结束或重验，不能无限有效。
4. 页面支持全屏、轮播、刷新及更严格脱敏的本地显示控制；这些是显示控制，不是业务数据写操作。无任务编辑/拖拽/状态变更入口。
5. 报表使用普通身份鉴权；给每个完成率/逾期率/趋势指标写出分子、分母、时间范围和删除/重开的处理规则，数值可对照样例数据手算。

**Gate：** 大屏数据路径 POST/PUT/PATCH/DELETE 为 405（Gin 显式启用相应行为）；无效/过期 token 401，范围不足 403；大屏 token 访问普通任务写接口或其他工作区被 401/403 拒绝；撤销影响请求与 SSE；响应中无禁止字段，脱敏不能降级；报表公式测试通过。

**Gate：** 搜索不越权；重复规则多 worker/重试/停机补跑幂等；模板实例是统一 Task；软删除→回收站→恢复/永久删除闭环；MVP 范围矩阵无遗漏。

## 14. S7/S8：P1 文件与敏感凭据

本节仅规定后续执行边界；MVP 不实现相关代码、表、配置和占位 UI。进入相应阶段前先完成 ADR，并同步 AGENTS.md 中有歧义的表述。

### S7：项目文件与 RustFS

**前置：** MVP 验收通过；文件存储/下载方案 ADR 有结论；RustFS 环境就绪。

1. 先处理“预签名 URL 与隐藏 bucket/key”的冲突：标准 S3 预签名 URL 通常包含 bucket/key。严格隐藏时选择后端流式代理；选择浏览器直连时必须先明确放宽对应条款及暴露范围，不能声称 URL 中不含 key。推荐首先实现代理，再按实际性能需求评估直连。
2. storage 内使用 aws-sdk-go-v2、BaseEndpoint、path-style、显式 region，只用标准 S3 API；迁移增加幂等 ensure bucket。接口按实际用例实现，不先包一整套用不到的 SDK。
3. 文件元数据与应用层版本是事实源；服务端生成 key；并发创建新版本用事务/唯一约束；不得靠对象 versioning 或 ETag 代替应用版本/SHA-256。
4. 状态流区分 pending、已上传待校验、ready、failed/quarantined；后端自行流式计算 checksum、校验 Content-Type/大小；若做分片直传，完成后由后端流式读回验证，不能直接信任客户端摘要。扫描未通过不可下载，不能上传结束就先 ready。
5. PG 事务内只写元数据/审计/补偿事件；S3 I/O 在事务外执行，有条件地推进状态。上传、新版、删除与元数据/Activity 原子写入；对象失败由重试/补偿/定期对账收敛。
6. 版本保留、清理任务、软删除后访问拒绝、历史版本下载、过期分片清理；响应 no-store，禁止记录文件内容、key、URL。
7. 锁定 RustFS 测试镜像；覆盖单次/分片/大文件流式、伪造类型、checksum 错误、并发版本、权限、对账、故障恢复与大屏拒绝。

**Gate：** 标准 API 与 path-style 验证、越权拒绝、补偿对账演练、内存占用与文件大小无整文件线性增长、扫描状态约束；代理模式下前端不接触存储寻址信息。

### S8：敏感凭据

**前置：** 推荐 S7 已完成；认证/权限/审计基础可用；加密/re-auth ADR 有结论。凭据不依赖 RustFS。

1. secrets 包独立实现 AES-256-GCM 信封加密；记录 wrapped DEK、nonce、key version，选择并固定项目/记录粒度及 AAD 绑定策略；KEK 只来自环境/KMS，不进入 DB、日志和示例。
2. 加密明文只在 secrets 内处理；app 调用受控接口，不能在其他包复制密码学实现。数据库只保存密文及必要元数据；默认 API 掩码，Activity 仅写安全摘要。
3. 默认 OWNER/ADMIN，其他角色需显式项目授权；reveal 与 copy 使用独立授权 action 和独立端点。re-auth token 原子消费，绑定 actor/session、资源和动作，TTL ≤ 5m，防止并发重放或跨资源使用。
4. reveal/copy 返回明文前先成功写 append-only 审计；审计失败时拒绝返回明文。拒绝尝试也留安全审计，避免因业务事务回滚一并丢失拒绝记录；用实际数据库权限验证不能 update/delete。
5. “复制经服务端”指先经 copy 端点授权并审计，再将一次性响应写入浏览器剪贴板；服务端无法直接写用户电脑剪贴板。是否成功写剪贴板可单独反馈，审计明确记录的是服务端授权释放。
6. 明确：授权且通过 re-auth 的 reveal/copy 响应允许一次性明文；列表、错误、其他响应、日志、通知、Activity、审计、大屏不得出现明文/密文。响应 no-store，前端不用持久化/查询缓存，自动隐藏，复制不复用已展示明文绕过审计。
7. 实现轮换、过期提醒、软删除/回收站、密钥版本兼容；演练旧/新密钥共存、分批重加密、错误 KEK 拒绝和备份恢复。丢失 KEK 的数据不可恢复，恢复手册需覆盖密钥保管。

**Gate：** 往返/篡改/错误密钥/版本测试；默认 MEMBER/VIEWER 拒绝、显式授权路径测试；未 re-auth/过期/重放拒绝；审计失败不出明文；大屏拒绝；日志/缓存无泄漏；轮换与密钥恢复演练成功。

| API/Webhook | 认证 scope、可靠事件/worker | 签名、重放、重试/死信、URL/SSRF 防护 |
| 导入导出 | Task/项目模型、异步任务与权限 | 预检、校验报告、幂等/部分失败、数据范围；凭据不批量导出 |
| 权限增强 | S1 已有工作区隔离与项目继承 | 覆盖/继承、失权、跨工作区拒绝回归 |

不是所有子项都可无条件并行；按当期依赖逐项实施。自动化复用已有业务事件定义和持久化入口，通知规则和自动化动作各自编排；不把通知内部级别/聚合状态当通用业务事件总线。

## 16. 不依赖 CI/CD 的本地 Gate

以下是 S0 要交付的统一命令接口。命令可以在 Windows PowerShell 逐条运行；每条成功后再执行下一条。带冒号的目标按工具兼容性使用引号。底层工作目录由 Makefile/脚本封装，不要求开发者猜测在哪个目录执行。

```powershell
make lint
make test
make build
make 'test:integration'
make 'test:e2e'
```

- `lint`：Go lint、前端 ESLint/格式检查；不能用自动修改格式掩盖未审查变更。
- `test`：domain/handler 等单元测试和前端测试；依赖真实服务的测试归 integration，不混用默认开发连接。
- `build`：api/worker/migrate 与前端生产构建，捕获只在构建时暴露的类型/SSR 问题。
- `test:integration`：真实 PG/Redis，P1 再加 RustFS；空库/升级/幂等/事务/并发由统一迁移入口构建 schema。
- `test:e2e`：只运行在隔离环境，覆盖当前阶段可用闭环；不能连接实际使用的数据库执行清理。
- 阶段内每完成可验证单元运行相应包/页面检查；阶段末再跑完整适用 Gate。纯文档改动检查文档与链接，不声称运行尚不存在的应用测试。
- 缺少环境、尚无某类功能的检查分别记录“阻塞”或“不适用及理由”。不适用必须符合当期范围，不能用于跳过已有功能测试。

### 每个阶段复制使用的清单

- [ ] 范围与前置决策明确；无 P1/P2 越界和假交互。
- [ ] 规则/契约及模型映射一致；没有第二套 Task/Today/Inbox DTO。
- [ ] 输入校验、集中错误映射、权限矩阵和跨工作区隔离覆盖。
- [ ] 写操作与 Activity 同事务，通知事件有可靠交接；无 GORM/S3 类型泄漏。
- [ ] 索引/约束和迁移影响已记录；全新库、升级、重复执行及失败恢复覆盖。
- [ ] 并发冲突、幂等、软删除、Clock/时区边界覆盖。
- [ ] UI 文案走 i18n；空、错、加载、重复提交、冲突反馈齐全。
- [ ] Config.Validate、环境变量示例、日志安全字段和依赖锁定同步。
- [ ] 本地适用命令全部成功；E2E/人工检查记录真实结果。
- [ ] 阶段记录包含版本、命令结果、schema/权限/通知影响、截图、已知限制与回退边界。

验收记录放入 `docs/verification/Sx-YYYY-MM-DD-<topic>.md`，使用统一验收模板。不把包含真实业务数据、密码、邀请 token 或预签名 URL 的原始日志/截图放进仓库。没有 PR 平台时，同样保留这些记录和 Conventional Commit 提交说明；本次仅落文档，不创建提交或发布。
